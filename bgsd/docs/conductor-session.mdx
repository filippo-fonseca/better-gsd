# Conductor sessions

The live session is the Conductor and Advisor. BGSD records its detected provider
and model, but does not replace it. The Conductor owns decomposition, unit seeds,
adaptive assignments, human gates, and all selector-driven setup.

Defaults apply only to pipeline lanes: Claude lanes use Opus at high effort;
OpenAI lanes use GPT-5.6 Sol at medium effort. A Codex Conductor you started at
GPT-5.6 high remains at that effort while it directs those independent lanes.

| Lane | Responsibilities |
| --- | --- |
| Build | Pipeline Agent, nested GSD phases, internal review, repairs |
| Evaluate | Loop 1 verifier, Loop 2 integration verifier, final fresh review |

`fixed` routing keeps all build units on the selected build model. In `adaptive`
routing, the Conductor must write a unit assignment with a reason. A missing
assignment resolves to the heavy model. Complexity still changes GSD workflow
depth but no longer chooses a model by itself. “Heavy” is a routing label for
the selected default build lane, not a promise of high effort: OpenAI's default
heavy lane is GPT-5.6 Sol medium.

Every selector uses the host’s native question UI. Do not replace the setup flow
with free-text questions. The session doctor must pass before spawning agents.

## Conductor cadence

Quick has an adaptive set of direct Pipeline Agents. The Conductor writes the
compact plan, decides whether one or several units are warranted, and chooses
serial or parallel execution. Workers edit, verify, and repair code in isolated
worktrees without invoking GSD. The Conductor reviews their evidence and steers
them; it never edits code during a BGSD session.

For Feature and Project, the Conductor remains the Advisor throughout. It must
write a seed before worker execution, inspect the worker control file and code
evidence at every phase change, commit, blocker, and verification result, then
rewrite the durable steering directive when the next action changes:

```sh
node "${CLAUDE_PLUGIN_ROOT}/scripts/advisor.mjs" steer \
  --run-id <run-id> --unit-id <unit-id> --message "<next direction>"
```

Pipeline Agents reread that directive at their required checkpoints. The worker
does not own product-level reasoning, routing, or integration decisions.
