## 1. Start a session

In **Claude Code**, **Cursor**, or **Codex** (after [Install](/install/)):

```
/bgsd-sesh "Add export filters to the settings page"
```

Equivalents if you prefer the terminal:

```sh
node bgsd/scripts/conductor.mjs "Add export filters to the settings page"
node bgsd/scripts/session.mjs --prompt "Add export filters to the settings page"
```

## 2. Choose your path

Every **new** session asks via native selectors (not prose):

1. **Recommended path preset** — Cursor default, Claude Code only, Claude + Cursor, Claudex, Codex only, or Custom mix
2. **Optional multi-select** — Claude Opus, Composer 2.5 Standard, Grok 4.5 Standard, GPT 5.6 Sol high, Custom…

Then **Doctor** validates what you picked. Details → [Models & routing](/models/).

## 3. Default workers (Cursor path)

- **Routine** → Composer 2.5 Standard (`composer-2.5`)
- **Hard** → Grok 4.5 Standard (`cursor-grok-4.5-high`) — recorded reason required

```
/bgsd-sesh "Add export filters"
```

## 4. Claude / Codex workers instead

Pick **Claude Code only**, **Claudex**, or **Codex only** in the selector — or pass flags:

```sh
node bgsd/scripts/session.mjs \
  --prompt "Add export filters" \
  --no-cursor \
  --profile claude-openai
```

## 5. Depth

| Override | Example |
| --- | --- |
| Slash / CLI | `/bgsd-sesh --feature "…"`, `--quick`, `--project` |
| Natural language | `Treat this as a project` |
| Selector | Quick / Feature / Project when scope is unclear |

| Mode | What happens |
| --- | --- |
| **Quick** | Direct workers in worktrees; no GSD |
| **Feature** | A few GSD units; Loop 2 when needed |
| **Project** | Full discuss → DAG → waves; human gate |

## 6. What to expect

1. Conductor scopes and decomposes
2. Workers build in isolated worktrees off `next`
3. Deterministic checks, then optional semantic evidence
4. Conductor adjudicates / steers repairs
5. Work merges to `next` — **never `main`**

Useful while it runs:

```
/bgsd-status
/bgsd-pause
/bgsd-gui
```
