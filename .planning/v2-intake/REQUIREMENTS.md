# Requirements: better-gsd (bgsd) — v2 Extension (Conductor Intake + Autonomous Proxy-Q&A)

**Defined:** 2026-06-29
**Extends:** the sealed v2 Conductor core (`/bgsd-run` + multi-worktree parallelism + control-file protocol + Loop 1 across worktrees). This is an ADDITIVE capability layer on top of v2 — it builds ON the v2 surface and reuses its machinery; it does not replace or re-open it.
**Core Value (this extension):** A front-door layer on the Conductor (Kiwi) for the user's hyperpolymath/JARVIS project. The user describes a project in natural language (voice, via hyperpolymath); a cheap model (**Haiku**) expands it into a large, exhaustive Markdown **intent spec**. Before any building, Kiwi runs an **active upfront brainstorm** — an interactive, highly-engaged discussion (phases, scope, gray-area decisions) — front-loading intent into the spec, a **decision record**, and a **preference profile**. Every human Q&A in that brainstorm uses **GSD-style selector answers** (pre-filled multiple-choice options PLUS an always-available "type your own" free-text option). Once parallel worktree agents run GSD pipelines and they (or the verifier) raise the normal GSD `discuss-phase` questions, **Kiwi answers them itself** from the upfront context via a **decision-oracle** with **confidence scoring** — high confidence → Kiwi auto-answers; low confidence → Kiwi escalates to the human, **rarely**, through the SAME selector Q&A. Never editing vendored GSD; only through bgsd's seams.

**The central design knot (what this whole extension is organized around):** GSD's `discuss-phase` and `gsd-new-project` expect a HUMAN answering via their question API (`AskUserQuestion`: options + an "Other"/freeform path, with `--text`, `--assumptions`, and `--auto` modes). The meaty seam is how Kiwi injects answers into that flow without touching GSD: a **decision-oracle** the Conductor populates from the upfront brainstorm (intent spec + decision record + preference profile), consulted on every discuss-phase question, with an **auto-answer path** gated by a **confidence threshold** — at/above threshold Kiwi answers as the user's proxy; below threshold Kiwi escalates via the v2 control-file escalation protocol surfaced as a selector Q&A. This extension specs how that oracle is built, how confidence is scored, and how it is driven **purely through GSD's seams** (the `/gsd-*` commands incl. `discuss-phase`'s `--assumptions`/`--text`/`--auto`/`--power` modes, the `.planning/` contract, and per-worktree `config.json`).

**Plan source:** `BETTER-GSD-DOCS/better-gsd-plan.md` — Part 1 §3 (whole-pipeline unit incl. the discuss chain), §5 ("Conductor answers itself first, escalates only if unknown"), §14 (Kiwi). Part 2 ("Conductor is the only human interface"). Part 3 §1–3 (control-file protocol: assumption-and-continue → clean-exit-on-blocker → answer-from-context → re-launch; user-escalation queue; "one consolidated question"). Part 11 (model + effort routing: decompose = Opus/xhigh; blocker triage = Haiku/low; answer-an-answerable-blocker = Sonnet/medium; doc/summarize = Haiku/low; two-knob escalation ladder; per-worktree × role × phase config seam). Part 13 §2–4, §7, §10 (token doctrine: scripts over models, pointers-not-blobs, structured outputs, shared research/decision cache). Part 16 (Kiwi identity + honest status line). GSD seam mechanics: `gsd-core/references/questioning.md` (the `AskUserQuestion` selector pattern + the freeform rule), `commands/gsd/discuss-phase.md` + `gsd-core/workflows/discuss-phase-assumptions.md` (assumptions/`--text`/`--auto` non-interactive modes — the auto-answer seam).

## Non-Functional Constraints (Hard Rules — enforced, not aspirational)

These apply to every requirement in this extension and must hold at all times. NFR-01..09 are inherited unchanged from v0/v1/v2; this extension adds NFR-10 (selector-Q&A-always) and NFR-11 (proxy-answer only at/above confidence, else escalate).

- [ ] **NFR-01 (Branch safety)**: This layer never writes, commits, pushes, or opens a PR to the default/production branch (`next`). Intake artifacts (spec, decision record, preference profile, oracle store) live only under `.bgsd/` and feed `rehearsal/<run-id>` + worktree branches exactly as v2; only the human merges `rehearsal/<run-id>` → `next`. (Plan Part 1 §9, Part 2; inherited.)
- [ ] **NFR-02 (Additive code)**: All code for this layer lives under the `bgsd/` namespace and writes only to `.bgsd*` runtime dirs (new: `.bgsd/intake/<run-id>/` for the spec/decision-record/profile, `.bgsd/oracle/<run-id>/` for the oracle store + audit log). It adds zero files into GSD's own directories. (Plan Part 1 §1, Part 10; inherited.)
- [ ] **NFR-03 (Never edit vendored GSD)**: The forked GSD source (root `commands/`, `agents/`, `gsd-core/`, `skills/`, `hooks/`, `.claude-plugin/plugin.json`) is read-only. The oracle drives `discuss-phase` ONLY through its documented flags/modes (`--assumptions`, `--text`, `--auto`, `--power`) and the `.planning/` contract — it never patches the questioning workflow or the `AskUserQuestion` call sites. (Plan Part 2, Part 12; inherited.)
- [ ] **NFR-04 (Seams only)**: The layer touches GSD only through the three stable seams — (1) GSD's `/gsd-*` slash commands (esp. `gsd-new-project` for the intake spec and `discuss-phase` for the per-phase questions), (2) the documented `.planning/` file contract (`PROJECT.md`/`REQUIREMENTS.md`/`CONTEXT.md`/`config.json` as the place answers land), (3) `config.json` / per-worktree `model_overrides`. The oracle injects answers by writing the `.planning/` files and by selecting the right non-interactive discuss mode — never by reaching into GSD internals. (Plan Part 1 §1, Part 11 two-level routing, Part 12; inherited.)
- [ ] **NFR-05 (Scripts over models / capture-then-summarize — "rule zero")**: The oracle store I/O, confidence-score arithmetic, the question→record matching/retrieval, threshold comparison, escalation-queue dedup, selector-payload assembly, and all intake/oracle file writes are deterministic scripts — never a model. Only the genuine judgment points call a model and get only their relevant slice: spec-gen (Haiku), brainstorm question-generation (Sonnet), an answerable-blocker answer that needs reasoning over the record (Sonnet/medium), blocker triage (Haiku/low). (Plan Part 11 "rule zero", Part 13 §1–6.)
- [ ] **NFR-06 (No silent green)**: The oracle never fabricates an answer to clear a blocker. When the oracle's confidence is below the threshold, or the spec/decision-record/profile genuinely does not cover a question, the layer abstains (returns `insufficient_spec`/`unknown`) and escalates rather than guessing — reusing the v2 honest-verifier `insufficient_spec` abstain discipline. A worktree whose escalation is unanswered parks in `needs_input` (never a fabricated `done`). (Plan Part 1 §5, Part 9 §5; inherited NFR-06; ADR-1738 honest-verifier abstain.)
- [ ] **NFR-07 (Conductor is the only human interface)**: Pipeline/Tester/verifier agents never prompt the user directly; they write blockers to control files the Conductor reads (the v2 protocol). The oracle answers answerable questions itself from the upfront context, and surfaces exactly one consolidated, deduplicated question to the user only for genuine unknowns, through the Kiwi channel. (Plan Part 1 §5, Part 2, Part 3 §2–3; inherited.)
- [ ] **NFR-08 (Bounded, reversible autonomy)**: Proxy-answering is bounded — the oracle answers within a configurable confidence threshold and a per-run cap on consecutive auto-answers before a mandatory user check-in; the upfront brainstorm and every escalation are auditable (each auto-answer logs the question, the chosen answer, the source record, and the score). The live multi-process orchestration this feeds remains human-gated exactly as v2 (off by default, `--dry-run` default, never CI, never `next`). (Plan Part 8 v2, Part 11 budget; inherited.)
- [ ] **NFR-09 (Context never overflows)**: The oracle is a small store of pointers + structured records, not a fat context; consulting it passes the relevant decision-record excerpt (pointer + slice), never the whole spec, to any model call. The intake spec is chunked and indexed so retrieval pulls only the matching section. (Plan Part 13 §2–4, §7, §10; inherited.)
- [ ] **NFR-10 (Selector-Q&A always — CRUCIAL HARD REQUIREMENT)**: EVERY human-facing question this layer raises — in the upfront brainstorm AND in any later escalation from a running worktree — is rendered as a **GSD-style selector**: 2–4 pre-filled, concrete multiple-choice options PLUS an always-available "type your own" free-text option (the `AskUserQuestion` / GSD selector pattern, honoring the freeform rule and `--text` plain-numbered-list fallback). No free-form-only prompt is ever shown to the human. Options must be concrete interpretations/choices, never generic ("Technical"/"Other"-only) buckets, and headers ≤12 chars per the GSD `AskUserQuestion` contract. (Plan Part 1 §5/§14, Part 16; `gsd-core/references/questioning.md` selector + freeform rule.)
- [ ] **NFR-11 (Proxy-answer only at/above confidence, else escalate)**: Kiwi answers a discuss-phase question AS the user's proxy if and only if the decision-oracle's confidence for that question is at/above the configured threshold; below the threshold it MUST escalate to the human (via the NFR-10 selector), never auto-answer. The threshold, the score, and the decision (auto-answered vs. escalated) are recorded for every question. High confidence → Kiwi answers; low confidence → human, rarely. (Plan Part 1 §5, Part 3 §2–3; this extension's central knot.)

## Extension Requirements (this layer)

Requirements for the Conductor Intake + Autonomous Proxy-Q&A layer. Each maps to exactly one roadmap phase (numbered E1–E6 as a v2 extension). Grouped by area: INTAKE, BRAINSTORM, PROFILE, ORACLE, ESCALATE, plus DOCS. The bulk is buildable + unit-testable deterministically (oracle store, confidence math, matching, threshold/escalation routing, selector-payload assembly) with **mocked model calls**; the genuinely interactive upfront brainstorm is isolated into its own criteria (interactive-by-design, see ROADMAP), and the live proxy-answer-during-a-real-run path rides the existing v2 `--live` gate.

### NL/Voice Intake → Rich Spec (INTAKE)

- [ ] **INTAKE-01**: `/bgsd-intake "<natural-language description>"` (also fed by hyperpolymath voice capture, reusing the v1 Hyperpolymath-capture → drop convention) is the front-door entrypoint. It opens an intake record under `.bgsd/intake/<run-id>/` and passes the raw description to a cheap **Haiku** spec-gen model call (Plan Part 11 "docs/summarize = Haiku/low") that expands it into a large, exhaustive Markdown **intent spec** (`SPEC.md`) — an explicit statement of intent covering goals, scope, surfaces, constraints, and open questions. The spec-gen call is the MODEL SEAM; the record/dir creation and write are deterministic (NFR-05). (Plan Part 11, Part 13 §6; reuses v1 capture drop.)
- [ ] **INTAKE-02**: The intent `SPEC.md` is chunked and indexed into addressable sections (goal, each scope area, each surface, constraints, glossary, open-questions) with stable section ids, so the oracle can later retrieve only the matching section (pointer + slice) for a given question — never loading the whole spec into a model call (NFR-09). The chunk index is a deterministic structure serialized alongside the spec. (Plan Part 13 §2/§7/§10.)
- [ ] **INTAKE-03**: The intent spec feeds GSD's project initialization through the seam only: the layer hands the `SPEC.md` to `gsd-new-project` (via its `--auto` "idea document via @ reference" path) so GSD produces its own `.planning/PROJECT.md`/`REQUIREMENTS.md`/`ROADMAP.md` from the user's intent, with zero edits to vendored GSD (NFR-03/04). The intake spec is the source-of-truth intent; GSD's generated planning files are downstream artifacts. (Plan Part 1 §1, Part 11; `commands/gsd/new-project.md` `--auto`.)
- [ ] **INTAKE-04**: The intent spec is never silently accepted as complete: the spec-gen output is validated to contain an explicit, non-empty **open-questions** section (the gaps the brainstorm must close), and an empty/degenerate spec is surfaced, not passed downstream (NFR-06). The spec records its provenance (raw input, model, timestamp) for the run ledger. (Plan Part 1 §12, Part 13 §6, NFR-06.)

### Active Upfront Brainstorm + Decision Record (BRAINSTORM)

- [ ] **BRAINSTORM-01 (INTERACTIVE by design)**: Before any decomposition/spawn, Kiwi runs an **active upfront brainstorm** — an interactive, highly-engaged discussion covering phases, scope boundaries, and gray-area decisions seeded from the spec's open-questions plus a gray-area analysis (reusing GSD's discuss-phase gray-area pattern). This is a deliberately interactive human session (the user is very engaged), front-loading intent — it is interactive **by design**, distinct from a live-orchestration human-gate. (Plan Part 1 §3/§5, `gsd-core/references/questioning.md` philosophy.)
- [ ] **BRAINSTORM-02 (selector-Q&A always — NFR-10)**: Every brainstorm question is presented as a GSD-style selector: 2–4 concrete pre-filled options PLUS an always-available "type your own" free-text option, honoring the freeform rule (when the user signals free explanation, switch to plain-text follow-up, then resume selectors) and the `--text` plain-numbered-list fallback for non-TTY. Selector payloads (header ≤12 chars, concrete non-generic options) are assembled deterministically; only the question-and-options generation is a model call (Sonnet, brainstorm reasoning). No free-form-only prompt is ever shown (NFR-10). (Plan Part 1 §5; `gsd-core/references/questioning.md`.)
- [ ] **BRAINSTORM-03 (decision record)**: Every brainstorm answer — whether a chosen option or a typed-own response — is captured into a structured **decision record** (`DECISIONS.md` + a machine-readable `decisions.json`) under `.bgsd/intake/<run-id>/`: each entry carries a stable decision id, the question, the option set shown, the user's selection (or typed text), the rationale/scope it locks, and links back to the spec section it resolves. The record is the durable, queryable substrate the oracle answers from (NFR-05 deterministic write). (Plan Part 1 §12, Part 13 §10.)
- [ ] **BRAINSTORM-04**: The brainstorm has an explicit decision gate (reusing GSD's "Ready? — proceed vs. keep exploring" selector): it loops, surfacing remaining open-questions, until the user confirms the intent is fully front-loaded, then seals the spec + decision record as the run's frozen intent baseline. Scope-creep suggestions are captured to a deferred-ideas list, never silently actioned (GSD scope guardrail). The sealed baseline is what every later proxy answer is derived from. (Plan Part 1 §3, `discuss-phase-assumptions.md` scope_guardrail + decision_gate.)

### Preference Profile (PROFILE)

- [ ] **PROFILE-01**: From the brainstorm answers + typed-own responses, the layer derives a **preference profile** (`profile.json` under `.bgsd/intake/<run-id>/`) — a structured record of the user's recurring preferences and defaults (e.g. stack/library leanings, scope-vs-speed bias, UX/verbosity tastes, risk tolerance) with each preference tagged by source decision and a strength weight. Profile derivation is a cheap deterministic roll-up over the decision record plus an optional Haiku summarize pass (Plan Part 11 docs/summarize = Haiku/low); it never invents preferences not grounded in an answer (NFR-06). (Plan Part 13 §10, Part 11.)
- [ ] **PROFILE-02**: The preference profile is a **secondary, lower-weight oracle source**: when a discuss-phase question is not directly answered by the spec or a specific decision record entry, the oracle may consult the profile for a defaulted answer, but a profile-only match carries lower confidence than a direct decision-record match (it expresses a leaning, not a locked decision) — feeding the confidence score (ORACLE-02) so profile-derived answers are more likely to fall below threshold and escalate. The profile is reusable across runs as a seed (cross-run preference continuity), written so it never leaks into `next`. (Plan Part 13 §7/§10, NFR-01/11.)

### Decision-Oracle + Confidence Scoring + discuss-phase Auto-Answer Seam (ORACLE)

- [ ] **ORACLE-01 (the oracle store + retrieval)**: The Conductor builds a **decision-oracle** for a run from the sealed baseline — a deterministic store under `.bgsd/oracle/<run-id>/` indexing the spec chunks (INTAKE-02), the decision record (BRAINSTORM-03), and the preference profile (PROFILE-01) into a queryable form (keyword/section index + structured fields). Given an incoming discuss-phase question (text + the worktree's phase/scope context), the oracle deterministically **retrieves** the candidate matching records (decision entries first, then spec sections, then profile leanings) and returns them with match metadata — pointers + slices, never the whole spec (NFR-05/09). (Plan Part 13 §7/§10; the central knot.)
- [ ] **ORACLE-02 (confidence scoring)**: For each retrieved candidate the oracle computes a deterministic **confidence score** in [0,1] from explicit signals: directness of match (exact decision-record hit > spec-section hit > profile leaning), match strength (keyword/semantic overlap), specificity (the record locks this exact gray-area vs. a general statement), source authority (sealed decision > spec prose > profile weight), and conflict penalty (contradicting records lower confidence). The score, its signal breakdown, and the chosen candidate are recorded for every question (auditable, NFR-08). Scoring is pure arithmetic — zero model calls (NFR-05). (Plan Part 11 difficulty-score precedent, Part 13 §6.)
- [ ] **ORACLE-03 (auto-answer seam into discuss-phase)**: When confidence ≥ the configured threshold, Kiwi answers the question **as the user's proxy without involving the human**, injecting the answer through GSD's seam only: the oracle writes the resolved decisions into the worktree's `.planning/` contract (the `CONTEXT.md`/config the discuss step consumes) and runs the worktree's GSD discuss step in a **non-interactive mode** (`discuss-phase --assumptions`/`--auto`/`--text`, selecting the mode that consumes pre-supplied answers) so GSD's questioning never blocks on a human (NFR-03/04). For a blocker raised mid-run via the v2 control file, Kiwi resolves it with the v2 `resolveBlocker` → `<agent-id>.inbox.md` → re-launch path, the answer sourced from the oracle. The answering reasoning, where a model is needed, is Sonnet/medium per Part 11 ("answer an answerable blocker"); triage is Haiku/low. (Plan Part 3 §1–3, Part 11; reuses v2 `control.mjs`.)
- [ ] **ORACLE-04 (threshold config + bounded proxy autonomy)**: The confidence threshold, the per-run cap on consecutive auto-answers before a mandatory user check-in, and the model postures for triage/answer are configured via the bgsd `config.json` block (extending the v2 `conductor` routing config), never by editing GSD. Every auto-answered question increments an audit log under `.bgsd/oracle/<run-id>/auto-answers.jsonl`. A threshold of 1.0 degrades gracefully to "escalate everything" (pure manual proxy off), proving the escalation path is always live (NFR-08/11). (Plan Part 11 config block, Part 13 §11.)

### Confidence-Gated Human Escalation via Selectors (ESCALATE)

- [ ] **ESCALATE-01 (confidence-gated escalation)**: When confidence < threshold, or the oracle abstains (`insufficient_spec`/`unknown`, NFR-06), Kiwi does NOT auto-answer — it routes the question to the user-escalation path. This reuses the v2 control-file escalation protocol exactly: the worktree's blocker becomes an `addEscalation` entry, the worktree parks in `needs_input`, and the Conductor aggregates it (`aggregateEscalations`) while the rest of the run continues unimpeded (NFR-06/07/11). (Plan Part 3 §3, Part 1 §5; reuses v2 `control.mjs`.)
- [ ] **ESCALATE-02 (one consolidated selector question)**: The Conductor surfaces escalations as **exactly one consolidated, deduplicated selector question** at a time through the Kiwi channel — and the escalation is rendered with the SAME GSD-style selector as the brainstorm: 2–4 concrete pre-filled options (synthesized from the best low-confidence candidates the oracle did find) PLUS the always-available "type your own" free-text option (NFR-10). Deduplication (collapsing the same gray-area raised by multiple worktrees) is deterministic (NFR-05). No free-form-only escalation prompt is ever shown. (Plan Part 1 §5, Part 3 §3, NFR-10.)
- [ ] **ESCALATE-03 (feedback loop — answer enriches the oracle)**: The human's escalation answer (chosen option or typed-own) is written back as a new sealed decision-record entry (BRAINSTORM-03 shape) AND, if it expresses a general leaning, into the preference profile — so the same or a similar question from another worktree later in the run resolves at high confidence without re-escalating (the oracle learns within and across runs). The answer flows to the waiting worktree via the v2 `resolveBlocker` → inbox → re-launch path. Escalations are rare by design; this keeps them rarer over a run. (Plan Part 3 §2, Part 13 §7/§10, NFR-11.)
- [ ] **ESCALATE-04 (rarity + honesty surfaced in status)**: Kiwi's escalation behavior is honest and visible: the `/bgsd-status` view (v2 STATUS surface, reused) shows, per run, the count of questions auto-answered vs. escalated, the running auto-answer rate, the current confidence threshold, and where a human selector is currently pending — so the human can see Kiwi is acting as a faithful proxy and that escalations are genuinely rare, never silently suppressed (NFR-06/08). Telemetry is captured deterministically (NFR-05). (Plan Part 16 honest status line, Part 13 §12; reuses v2 STATUS-03.)

### Docs (DOCS)

- [ ] **DOCS-07**: A `/bgsd-intake` + upfront-brainstorm usage page (GSD-Mintlify style, diagram-first) documents the intake flow end-to-end — NL/voice → Haiku spec-gen → chunked intent spec → active upfront brainstorm (selector Q&A) → sealed decision record + preference profile → feed into `gsd-new-project` — including the selector-Q&A-always rule and the "interactive by design" nature of the brainstorm. (Plan Part 14, Part 16; mirrors v0/v1/v2 docs cadence.)
- [ ] **DOCS-08**: A decision-oracle + proxy-Q&A page documents how Kiwi answers discuss-phase questions as the user's proxy — the oracle store, the confidence score + threshold, the auto-answer-into-`discuss-phase` seam, and the confidence-gated escalation via selectors — with the auto-answer/escalation decision diagram, the audit log, and the exact config knobs (threshold, auto-answer cap). (Plan Part 14, Part 11, Part 16.)

## Deferred — Out of Scope for this Extension

Tracked but explicitly NOT in this extension's roadmap. Promoted into Active scope only at a future boundary.

- **EXT-DEF-01**: Real-time bidirectional voice during the brainstorm (full duplex speech), beyond hyperpolymath capture feeding text intake. The selector Q&A is rendered in the terminal/Kiwi channel; voice-driven selection is future. (Plan Part 16.)
- **EXT-DEF-02**: A globally-persistent, cross-project preference profile that auto-applies to every future project without per-run sealing. This extension writes a per-run profile that can be reused as a seed (PROFILE-02), but a fully global learned profile + its privacy/versioning model is deferred.
- **EXT-DEF-03**: An oracle that learns from post-merge outcomes (which auto-answers later proved wrong after Loop 2 / user-eval) to re-weight confidence. Loop 2 + user-eval are v3; closing that outcome→confidence loop waits for them. (Plan Part 8 v3.)
- **EXT-DEF-04**: Auto-answering NON-discuss high-stakes decisions (merge-conflict resolution, decompose) from the oracle. Those stay on their v2 model postures (Opus); the oracle proxies the discuss-phase question class only.

## Out of Scope (this extension)

| Feature | Reason |
|---------|--------|
| Re-opening or modifying the sealed v2 Conductor core (`run.mjs`/`control.mjs`/`decompose.mjs`/scheduler/merge) | This is an ADDITIVE layer ON v2; it reuses v2 machinery (control-file escalation, routing config, status view) and adds the intake + oracle, it does not rewrite v2 |
| Editing GSD's `discuss-phase`/`new-project`/`questioning.md` to inject answers | Hard rule NFR-03 — answers are injected only via the `.planning/` contract + the non-interactive discuss modes (`--assumptions`/`--auto`/`--text`); zero edits to vendored GSD |
| Any free-form-only human prompt | NFR-10 — every human question (brainstorm + escalation) is a selector with options + "type your own"; no exceptions |
| Auto-answering below the confidence threshold | NFR-11 — below threshold the layer MUST escalate; it never guesses to clear a blocker (NFR-06) |
| Live multi-process proxy run in automated CI | Inherits v2 SPAWN-04 human-gate; the live proxy-during-a-real-run path rides the existing `--live` gate, off by default, never CI, never `next` |
| Loop 2 / user-eval outcome-driven oracle re-weighting | v3 (EXT-DEF-03); this extension seals intent upfront and answers from it, no post-merge feedback loop |
